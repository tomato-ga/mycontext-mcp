# 編集プレイブック

このプレイブックは、大野恭希（ギズモード・ジャパン元編集長、メディアジーン→HF.M代表）が蓄積した編集ノウハウ——PECO向け「メディアと編集研修」全8回（2017〜2018）、編集十訓、HF.M編集ドキュメント群（2016）、Evernote企画メモ——から、**原稿が上がってから公開し、公開後に改善するまでの編集作業**を、作業の順番に再編成したものである。姉妹文書「企画構成プレイブック」が企画〜構成案〜本文構成という「書く前」の工程を担うのに対し、本書は「すでに上がってきたもの」を判断・修正する工程を担う。各章末の（→No.X）は姉妹文書「コンテンツ企画案カタログ」の該当エントリを指す。

## 1. このプレイブックの使い方

編集は原稿を直す作業ではなく、**このコンテンツを公開してよいかを判断する仕事**である。判断の材料を揃える手順が本書の第3章から第9章、判断を支える原則が第2章、判断を実行に移すコミュニケーションが第10章、判断の結果を検証するのが第11章にあたる。

研修資料「編集作業の13のチェックポイント」は本書全体に再配置してある。対応は次のとおり。

- CP1〜3・10（需要・自社文脈・コンセプト整合・ターゲット）→ 第4章
- CP4（タイトル）→ 第5章、CP5・7（構成・メッセージ）→ 第6章
- CP6・9（出典・事実確認）→ 第7章、CP13（法律）→ 第8章、CP8（校正）→ 第9章
- CP11（外部コミュニケーション）→ 第10章、CP12（やらないこと）→ 第3章

使い分けの原則: タイトルや構成は企画構成プレイブックにも登場するが、あちらは**設計の手順**（ゼロから作る）、本書は**検査とリライトの手順**（上がってきたものを判定する）として読む。自分名義の原稿の文体レベルの編集（段落構成・逆アウトライン・語尾・結び方）は ore-body-style（edit-structure / edit-voice）を正とし、本書では扱わない。

## 2. 編集の原則（判断の土台）

編集の定義は「**ターゲットの関心に合わせ、ターゲットが知りたいコンテンツを作り出すこと**」。メディアが伝えたいメッセージとユーザーニーズの交わる部分を考え出すのがウェブ編集であり、コンテンツと読者のニーズが完全にシンクロする状態（コンテンツマーケットフィット）を狙いにいく。編集の定義は人・企業・媒体によって違っていてよいが、自分なりの定義を持たずに編集判断はできない。

手を動かす場面での基本操作は4つしかない。

1. **削る**: 冗長・重複・脱線を除去する
2. **組み合わせる**: バラバラの情報を論理的に再配置し、流れを作る
3. **直す**: 誤字脱字・事実誤認・不正確な表現を修正する
4. **何もしない**: 著者の意図・個性が活きている部分はそのまま残す

「何もしない」も編集判断であることが最重要で、直しすぎは著者の熱を殺す。バランスは**テクニック2〜3割、マインド7〜8割**。技術的な修正よりも、読者への想い・熱量・メッセージの強さを重視する。結局大事なのはバイブス（コンテンツに込める熱量・空気感）であり、それを支える心構えは「利己的であるよりも利他的であること。Give Give Give」。自分が書きたいことを書くなら日記か個人ブログでやる——メディアで公開する以上、新たな視点の提供や有益な情報という他者への貢献が前提になる。

判断に迷ったときの拠り所として、編集十訓の要旨を挙げる。①編集者は一流のビジネスマンたれ（社会を広く深く理解する）、②読者の共感を得てこそ価値。常に読者の側に立ち、その半歩先を行く、③使命は読者から信頼されるコンテンツ。虚偽と事実の歪曲を絶対に戒める、④コンテンツは企画が生命。読者ニーズの発掘に努める、⑤決定した企画は万難を排して100%実現する、⑥企画の成否は最適な著者の発掘にかかっている、⑦時流に惑わされず真理を見抜く眼を養う、⑧リリース計画の厳守。遅れが諸悪の根源、⑨校正はコンテンツの真価を発揮させる最後の機会、⑩できあがったコンテンツがすべて。弁解は通用しない。

## 3. 受領時の突き合わせ（編集の入口）

原稿を受け取ったら、赤を入れる前に**構成シートとの突き合わせ**を行う。企画構成プレイブック8-9の構成シート（タイトル案・想定読者・読後変化・中心命題・見出しリストと各セクションの役割）と原稿を照合し、意図どおりに書かれているかを最初に判定する。意図とズレた原稿を編集で立て直すのは骨が折れるうえ、高確率で失敗する——ズレの原因が企画側（構成案が曖昧だった）にあるなら、原稿をいじる前に企画へ戻して決着させる（→No.89）。

同時に、**やらないことの確認**（CP12）をここで通す。メディアとして絶対にやらないことに触れていたら、以降の細かい編集に進む前に差し戻しまたは没にする。

- 文体の逸脱（メディアのトーンと合わない書き方）
- ユーザーを欺く表現(誇大表現・釣りタイトル)
- コピペ・画像の無断使用
- その他メディアの色と合わないもの

「メディアの色と違うから」という言語化しにくい判断を個人の勘で終わらせないために、編集方針ドキュメントに紐づけて説明できる状態を保つ。うまくいっているメディアといないメディアの違いはドキュメントの有無にある（第11章参照）。

## 4. 全体評価 — 需要・文脈・整合性

細部より先に、このコンテンツは出す価値があるかを4点で評価する。

**需要**(CP1): 今ウェブで供給が足りていないものか。企画段階の検証が甘い原稿はここで露呈する。需要の探し方は5系統——ソーシャルブックマーク(平均ブクマ数100または200以上で、1年以上類似コンテンツが話題になっていないもの)、SNS検索で話題を遡る、Amazonのロングセラー傾向、人気ハッシュタグ、雑誌・経済メディアのトレンド。具体的なサービス名は2010年代の例であり、現行の同等サービスに読み替える。ネタを見つけたら3ステップで分析する: ①対象となるコンテンツをピックアップ、②そのコンテンツは「誰に何を伝え、どうしてもらいたかったのか」を分析、③同一の切り口で、対象ユーザーへもっと価値を届けるためには何をすべきかを考える。判断基準は「**今のタイミングで、このユーザー層へ、このネタを投下したら、これくらいのPV・再生数は獲得できる**」と明言できること。類似・競合コンテンツの数字調査で裏付けを取り、なんとなく面白そうで通さない。

**自社メディアの文脈**(CP2): 今、自社メディアはどこへ向かおうとしているのか。方向性を理解せず個々の記事を通すと全体の統一感が崩れる。

**コンセプト・ミッションとの整合**(CP3): 企画がコンセプトから逸脱していないか毎回確認する。コンテンツは常に編集方針の傘の下にある。

**ターゲット**(CP10): このコンテンツは誰に読んでもらいたいのか。企画段階で設定した「実在する人」（企画構成プレイブック第2章）が、完成原稿でブレていないか。あわせて有益性の2軸——おもしろいか（感情に訴える）、役に立つか（勉強になる・仕事に使える・生活を便利にする）——のどちらかを必ず満たしているかを見る。どちらも満たさない記事はスルーされるだけである。

## 5. タイトルの編集

タイトルの原則は「その記事がどんな内容なのか一目で分かり、人を惹きつけられるもの」。コツは**必要な情報を、分かりやすく配置させる**こと。上がってきたタイトルは次の4項目で検査する。

1. 自分は読むか？ターゲットは読むか？
2. 必要なキーワードは入っているか？
3. 声に出したら読みやすいか？
4. ここぞ！という時の記事は50個以上タイトルを考えたか？

通常記事でも編集段階で最低20案は出し直してみる。タイトルを考え直す行為自体がターゲット理解を深め、本文の弱点も見えてくる。行き詰まったらウェブ上の成功しているタイトルの構造・パターンを遠慮なく分析して応用する(タイトルをパクる)。文字数・ゴールデンスペース・数字・ターゲット明示といった設計時の型10パターンは企画構成プレイブック第4章(→No.15)を参照し、本章はその検査側と位置づける。

## 6. 構成・ロジック・文章の編集

構成の検査は3つの観点で行う（CP5）。

- **基本フレーム**: 起承転結が機能しているか。5W1Hが分かるか
- **感情設計**: 各セクションで読者がどう感じるかが設計されているか。読者の反応と感情はコンテンツを作る前に設計するものであり、原稿にそれが表れているかを見る
- **音楽的比喩**: 起=イントロ（つかみ）、承=Aメロ（展開）、転=Bメロ（新しい視点）、結=サビ（核心・最も印象に残る部分）。サビのない記事、イントロが長すぎる記事はここで捕まえる

そのうえでチェックする——記事の流れは分かりやすいか、ロジカルに説明できるか、価値のある記事内容になるか、そして**そのコンテンツに「意思」はあるか**。データ分析だけでなく作り手の熱量がコンテンツの質を左右する。

**メッセージチェック**（CP7）: この記事で何が言いたいのか一文で言えるか。主張（メッセージ）と説明は十分か。記事内のテーマは1つだけに絞る——何が言いたいのか分からない記事は価値が低く、複数テーマの同居は切り口の未決定を意味する。テーマが割れていたら分割か削除で決着させる。

文レベルの編集では言い回しを工夫し、国語辞書・類語辞書を開きながら磨く。自分名義の原稿は ore-body-style（edit-structure / edit-voice）の手順——逆アウトライン、事実と主観の分離、語尾・結び方——を正とする。

## 7. 出典・事実確認

**出典チェック**（CP6）: 引用元は確認したか、URLは正しいか、リンクは実際にアクセスできるか。1記事1ソースの要約は禁止——複数情報源から独自の記事に仕立てる（→No.136）。競合ソースの受け売りは一次情報チェックを経る（企画構成プレイブック第1章と同じ一次情報主義）。

**事実確認・裏どり**（CP9）: 数値データ・引用・固有名詞・日付など、事実に関わる記述の正確性を確認する。製品名称・固有名詞の確認は公開前チェックの原型（2012年から不変）に含まれる基本項目。エビデンスに近い記述は元情報まで遡って確認し、強すぎる言葉は柔らかい表現に落とす。虚偽および事実の歪曲は絶対にこれを戒めよ（編集十訓③）——信頼はメディアの唯一の資本であり、事実確認はコスト削減の対象にしない。

## 8. 法務・レギュレーション

公開判断の最終関門(CP13)。確認する領域は4つ。

- **著作権法**: 引用ルールの遵守（主従関係・出所明示・改変禁止）、画像・文章の無断使用がないか。DMCA濫用のような制度の不正利用に加担しないこと
- **薬機法**: 健康・医療系の効果効能の記載。広告該当性は広告主の有無ではなく「特定商品の購買を誘引するか」で判断される。①顧客誘引の意図が明確、②特定商品名の明示、③一般人が認知できる状態——3要件を満たすと広告主なしでも規制対象になりうる（弁護士確認済みの整理。本章を正本とし、企画構成プレイブック第5章の記載は要旨）
- **景品表示法・消費者庁の動向**: 優良誤認・有利誤認にあたる表現がないか。規制動向は変わるため、規制領域の記事はリーガルチェックの体制を通す
- **広告の透明性**: [PR]表記を外す・広告に見えないようにするといった過去の慣行は採用しない。ユーザーを欺かないこと（第3章のやらないこと）が優先する

## 9. 校正と表記統一

校正はコンテンツの真価を発揮させる最後の機会である(編集十訓⑨)。「ミスはなくて当然」の状態になりきって全文を精読する(CP8)。

- 誤字脱字: 公開前に必ず全文精読。ツールに頼ってよいが最終判断は目視
- **表記統一リストの運用**: 漢字を開くか閉じるか（「いとこ」「親せき」等）をメディアとして決め、判断が発生するたびにリストへ追加していく。リストは編集方針ドキュメントの一部として蓄積する（→No.136）
- キャプションと本文の整合: キャプションは画像の説明であり、無理に本文へ接続しない
- ランキング・比較記事: 何を根拠にした順位かを明示する

## 10. ライター・外部とのコミュニケーション

編集判断を原稿に反映させる手段は、ほとんどの場合ライターへのフィードバックである（CP11）。原則は3つ。

- **相手の反応を見る**: 指示が伝わっているか、モチベーションはあるか
- **強み弱みの把握**: 何ができて何ができないか。優れた著者の得意分野を引き出して企画の意図を全うする（編集十訓⑥）
- **課題の発見**: 上がりが悪い根本原因はお金か、時間か、スキルか。根本的な問題を見つける努力をする

赤入れを返すときは、直す理由を第2章の原則と編集方針ドキュメントに紐づけて言語化する。「なんとなく違う」で返すと同じズレが再発する。交渉ごとの基本フレームは「相手が何を欲しがっているのか」×「自分が提供できるものはなにか」。すべては円滑に仕事を進めるためであり、目的は原稿の品質と締切の両立にある。リリース計画の厳守は編集者に不可欠の条件——遅れが諸悪の根源であることを銘記する（編集十訓⑧）。クライアントが関わる記事のオリエン項目と進行は企画構成プレイブック第3章（→No.1）を参照。

## 11. 公開判断と公開後の編集

公開前の最終チェックは1枚で行う。第3〜9章を通過していることを次の順で確認する。

1. 構成シートと一致しているか。やらないことに触れていないか（第3章）
2. 需要の数字的根拠・自社文脈・コンセプト・ターゲットが揃っているか（第4章）
3. タイトル4項目を通過したか（第5章）
4. 流れ・ロジック・意思があり、テーマが1つに絞れているか（第6章）
5. 出典と事実確認が済んでいるか（第7章）
6. 法務4領域を通過したか（第8章）
7. 全文精読と表記統一が済んでいるか（第9章）
8. 最後に——その記事で何が言いたいのかハッキリしているか、共感されるタイトル・内容か

公開したら終わりではない。**公開後の編集**を工程として持つ。アクセス分析は健康診断（全体把握）→来訪元チェック→入り口ページ→離脱率→コンバージョンの順に見て、改善候補を特定する。タイトル差し替え・リライトは、需要はあるのに入り口で負けている記事から優先する。古い検索アルゴリズムやSNS仕様に依存した施策は原則だけ残して現行仕様を再確認する。

最後に運用の土台について。編集判断のブレを止めるのは編集方針のドキュメント化である。言語化されにくいポリシーを練って文章化したドキュメントは、トンマナの統一、迷ったときに原点へ戻れるツール、チーム間連携、引き継ぎの容易化として機能する（→No.89）。本プレイブックもその一部であり、表記統一リスト（第9章）ややらないことリスト（第3章）は運用の中で更新し続ける。継続によって蓄積されるコンテンツは資産である。2016年に作られた記事がいまも読まれるように、いま公開する記事もこれから先ずっと読まれる。魂を込める。
