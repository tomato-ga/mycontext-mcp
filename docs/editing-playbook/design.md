## 1. 目的と位置づけ

「企画構成プレイブック」（kikaku-composition-playbook）の姉妹文書として、**原稿が上がってから公開するまで（および公開後）の編集作業**を、作業の順番に再編成したプレイブックを作る。

プレイブックシリーズの分担は次のとおり。

| 文書 | 担当工程 | 状態 |
|---|---|---|
| 企画構成プレイブック | 企画 → 読者設計 → 構成案 → 本文構成（書く前） | 稼働中 |
| **編集プレイブック（本設計）** | 原稿受領 → 編集 → 校正校閲 → 公開判断 → 公開後改善 | 新規 |
| コンテンツ企画案カタログ | 427件の事例索引（両プレイブックから →No.X で参照） | 稼働中 |
| ore-body-style（edit-structure / edit-voice） | 自分の文体レベルの編集規範 | 稼働中・参照のみ |

境界線の原則: **企画構成プレイブックは「これから作るもの」を設計する。編集プレイブックは「すでに上がってきたもの」を判断・修正する。** 同じ題材（タイトル、構成、品質チェック）が両方に登場するが、前者は設計手順、後者はチェック・リライト手順として書き分ける。

## 3. 章構成（本文設計）

原稿を受け取ってから公開するまでの時系列に、13チェックポイントを再配置する。括弧内は主要ソース。

### 第0章 このプレイブックの使い方
- 姉妹文書マップと境界線（第1節の表を要約）
- 「編集は原稿を直す作業ではなく、公開してよいかを判断する仕事」という視点の宣言

### 第1章 編集の原則（判断の土台）
- 編集の定義: メディアのメッセージとユーザーニーズの交点（編集の考え方.docx）
- 編集の4つの基本操作とバランス（lesson-02/04「編集の本質」）
- 編集十訓の10原則（編集十訓.docx。読者への信頼、事実、締切、校正）
- 「ターゲットが知りたいものを作る」「制作は準備が重要」（HF.M）

### 第2章 受領時の突き合わせ（編集の入口）
- 構成シート（企画構成プレイブック8-9）と原稿の一致確認。ズレていたら直しに入る前に企画側へ戻す
- チェックポイント12「やらないことの確認」をここに置く（直しすぎの抑止）

### 第3章 全体評価 — 需要・文脈・整合性（CP1〜3）
- コンテンツ需要の判断（需要を探す5つの方法）
- 自社メディアの文脈理解
- コンセプト・ミッションとの整合性
- ターゲット設定の検証（CP10。企画構成プレイブック第2章の「実在する人」原則を編集側から再検査）

### 第4章 タイトルの編集（CP4）
- タイトル原則・チェックリスト4項目・「タイトルをパクる」（lesson-04）
- 企画構成プレイブック第4章（設計時の型10パターン →No.15）との分担: あちらが生成、こちらが検査とリライト

### 第5章 構成・ロジック・文章の編集（CP5・CP7）
- 構成の作り方3種（基本フレーム・感情設計・音楽的比喩）を検査観点に反転
- メッセージチェック（この記事で何が言いたいのか一文で言えるか）
- 逆アウトライン・事実と主観の分離・語尾: 自分名義の原稿は ore-body-style（edit-structure / edit-voice）を正とし、ここでは手順名だけ示す

### 第6章 出典・事実確認（CP6・CP9）
- 参照元・ソースのチェック（1記事1ソース要約の禁止、一次情報主義）
- 校閲・裏どりの手順（固有名詞・数値・引用の確認）

### 第7章 法務・レギュレーション（CP13）
- 薬機法広告該当性の3要件（企画構成プレイブック第5章の要旨を正式にこちらへ移し、あちらは参照に変える案。→未決事項1）
- 著作権・引用・写真利用の基本

### 第8章 校正と表記統一（CP8）
- 誤字脱字チェックの手順
- 表記統一リストの運用（開く/閉じる、出てきたたびに追加 →No.136）

### 第9章 ライター・外部とのコミュニケーション（CP11）
- 赤入れの返し方（直す理由を原則=第1章に紐づけて伝える）
- 外部関係者・クライアントとの調整（lesson-05 第4節、No.1 制作マニュアル）

### 第10章 公開判断と公開後の編集
- 公開前最終チェックリスト（13CPを1枚に統合。企画構成プレイブック8-12と同型式）
- 公開後: PV改善・リライト・タイトル差し替えの判断基準（Evernoteインベントリ領域4から Phase 0 で追加抽出）
- 編集方針のドキュメント化と更新運用（「編集方針をドキュメント化する実践法」）

分量目安: 全体で 12,000〜16,000 字。配信上限 20,000 字（MAX_PLANNING_PLAYBOOK_CONTEXT_CHARS と同値）に対して余裕を残す。

## 4. 配信経路の設計

本文量が小さいため、企画構成プレイブックの章分割モデルは使わない。メディア運営プレイブックと同じ全文1レコードモデルに統一する。

- **Notion**: MyContext Documents DB に新規ページ「編集プレイブック」を作成
  - Category: `Editor Knowledge` / Schema Version: `editor-knowledge-v1` / Sync Source: `Notion`
  - Document ID: `henshu-editing-playbook`（kikaku-composition-playbook と対になる命名）
- **mycontext-sync / sync-worker**: `"henshu-editing-playbook"` と `"knowhow-media-design"` を `whole_document` と判定する
  - 本文は `editor_knowledge_documents` の1行に保存
  - `section_revision_sha256` / `section_count` / `search_span_count` は `NULL`
  - 同期時に当該文書の旧 `editor_knowledge_sections` 行を削除
- **MCP一般検索**: `section_count IS NULL` の全文検索経路へ載せ、検索IDを `editor-knowledge:henshu-editing-playbook` の1件に固定する
- **mycontext-mcp-worker**: 全文専用ツールは維持する
  - `src/editingPlaybook.ts`（SOURCE_ID / DOCUMENT_ID / 20k 上限 / Context 型 / エラー型）
  - `src/tools/getEditingPlaybookContext.ts` + `register.ts` 登録
  - テスト: `tests/getEditingPlaybookContext.test.ts`（unit）と `tests/liveEditingPlaybook.test.ts`（live）を planning playbook のテストからミラー

**専用取得ツール `get_editing_playbook_context`（全文・非切り詰め）を正規経路とする**。一般検索・`read_context` でも章IDではなく全文文書IDを返す。
